# Практика: Функциональные требования (FR)
**Дата:** 14.10.2026
**Тема:** [[Функциональные требования]]

## Контекст фичи
**Функция:** Применение промокода при оформлении заказа.
**Пользовательская история (US):** Как покупатель, я хочу применить промокод в корзине, чтобы получить скидку на заказ и сэкономить деньги.

## Функциональные требования (FR)

### 🟢 Основной сценарий (Happy Path)
- **FR-01:** При нажатии кнопки "Применить" с валидным промокодом (промокод существует в базе данных, имеет статус "Активен", текущая дата находится в пределах срока его действия,  лимит по сумме заказа достигнут и в корзину входят товары  соответствующей категории), система должна отобразить сообщение "Промокод применен" под полем ввода.

- **FR-02:** При нажатии кнопки "Применить" с валидным промокодом (промокод существует в базе данных, имеет статус "Активен", текущая дата находится в пределах срока его действия,  лимит по сумме заказа достигнут и в корзину входят товары  соответствующей категории), система должна вывести итоговую сумму заказа с учетом скидки.

### 🔴 Обработка ошибок и граничные условия (Edge Cases)
- **FR-03:** При нажатии кнопки "Применить" с незаполненным полем или с полем заполненным только пробелами, система должна вывести текст "Введите промокод", под полем с промокодом.

- **FR-04:** При нажатии кнопки "Применить" с промокодом имеющим статус "Неактивен", cистема должна вывести текст "Срок действия промокода истек", под полем с промокодом.

- **FR-05:** При нажатии кнопки "Применить" с промокодом который ранее уже использовался данным пользователем, cистема должна вывести текст "Промокод не может быть использован повторно", под полем с промокодом.

- **FR-06:** При нажатии кнопки "Применить" с промокодом у которого минималоная сумма заказа больше суммы текущего заказа пользователя, cистема должна вывести текст "Минимальная сумма заказа не достигнута, пополните корзину для применения промокода", под полем с промокодом.

- **FR-07:** При нажатии кнопки "Применить" с промокодом имеющим в базе данных статус "Активен" и в поле категории товара имеет значение отличное от "Все" при этом в корзине нет товаров из перечисленных категорий, система должна вывести текст "В корзине нет категорий товаров на которые распространяется данный промокод".

- **FR-08:** При нажатии кнопки "Применить" с промокодом имеющим лишние пробелы перед и/или после промокода, система должна автоматически удалять пробелы в начале и в конце строки перед валидацией.
## Анализ ценности (Техника "5 Почему")
**Выбранное FR:** **FR-06:** При нажатии кнопки "Применить" с промокодом у которого минималоная сумма заказа больше суммы текущего заказа пользователя, cистема должна вывести текст "Минимальная сумма заказа не достигнута, пополните корзину для применения промокода", под полем с промокодом.

1. Почему система должна это делать? → Чтобы пользователь **понял**, почему промокод не применился, и мог принять решение — добавить товары или отказаться.
2. Почему это важно для пользователя/бизнеса? → 
    - Это важно для того чтобы пользователь мог принять **осознанное решение**: добавить товары в корзину или отказаться от промокода.
    - Это важно для бизнеса, потому что таким образом покупателя побуждают на более крупные покупки.
3. Почему это решает проблему? → Потому что увеличивает **средний чек** (AOV — Average Order Value).
4. Почему мы делаем это именно так, а не иначе? →  Потому что скидка дается только на **большой заказ**, где маржа покрывает эту скидку. На маленьком заказе скидка была бы убыточна.
5. **Почему** это важно стратегически? 
   → Потому что увеличение AOV напрямую влияет на **выручку** и **LTV** клиентов без увеличения стоимости привлечения (CAC).

**Вывод:** Требование FR-06 решает бизнес-задачу (рост выручки через AOV), улучшает UX (прозрачность) и защищает маржинальность (скидка только на прибыльных заказах).
